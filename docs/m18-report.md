## Pronunciation results

What was built: the host's dictionary-based phonemizers now **report the words their dictionary lacks**, and the host stops **before rendering** with exit 11 (`pronunciation_unknown`); BLT maps each word onto the plan and
names it with voice, bar and beat. Nothing is guessed, no syllable is dropped. `--allow-unknown-words` exists for tests only.

| Engine | A word CMUdict has | A word CMUdict lacks | Evidence |
|---|---|---|---|
| `ArpasingPhonemizer` | renders | **stops, named per voice** | host matrix (3 unknown words: `ev'ry`, `o'er`, an invented `blorptastic`), fixture scores, hint test |
| `EnglishVCCVPhonemizer` | renders | **stops, named per voice** | same |
| `EnXSampaPhonemizer` | renders | **stops, named per voice** | same |
| default (alias) phonemizer | n/a (the lyric is the alias) | not looked up; an alias the voicebank lacks is reported afterwards as silent notes (`STEM_NOTE_SILENT`), unchanged | existing tests |

Fixture scores (8 bars, 4/4, 88 bpm; all four voices; contractions `don't`, `we'll`, `I'm`, `'cause`; `together` on three notes; a melisma on `sing`; half and whole notes):

* **known words**: all three engines, no refusal, 13 tracks. **Respelled words** (`loved`, `mommy`, `everyone`, `beneath`, `over`): same.
* **unknown words** (`lov'd` bar 1 beat 1, `mammy` bar 2 beat 4, `ev'ryone` bar 4 beat 1, `'neath` bar 6 beat 3, `o'er` bar 7 beat 1): all three engines stop and name **exactly these five**, each with all four voices, and no WAV is written. One unknown among known words names only that word.
* A phonetic hint (`ev'ry[eh v r iy]`, X-SAMPA `E v r i`) makes an unknown word render on all three engines, confirming the mechanism for the override design; the hint's symbols must be the phonemizer's own (Arpasing silently drops an invalid one, which the design guards against).

**Defects found by this work and fixed:**

1. **English VCCV and X-SAMPA rendered nothing in the host at all.** They load their dictionary on a background task and answer "empty" until it finishes; the headless host never waited. (`Phonemizer.Testing = true` makes them synchronous.) Before M18 neither could have produced singing with this host.
2. **Arpasing treated a word it did not know as a voicebank alias** rather than reporting it.
3. A word spread over several notes reached the phonemizer as separate syllable fragments, so `together` would have been looked up as `to`, `ge`, `ther`. It is now sent whole (first note carries the word, later notes the `+` extender) when the score gives the complete begin/middle/end chain on touching notes.
4. Follow-the-Lead now copies the syllable role (begin/middle/end) from the Lead note, which the whole-word logic needs.
5. **CI failure on `c4908c9`/`08d009c` (found by CI, not by me locally): the negative control host could not compile** against the unpatched OpenUtau because the host now uses the interface that BLT's patch adds. The control build now includes a stub of that interface only; the control still proves all three checks refuse the unpatched host (local and CI).
6. **CI failure on `c4908c9`: an existing race in `FileLock`** (`test_concurrent_renders_do_not_collide`, `HOST_LOCK_UNAVAILABLE: Permission denied`). Two first openers of a new lock file both wrote an initial byte; Windows locks are mandatory, so the second write hit the byte the first had locked, and the buffered handle re-raised on close. Unbuffered handle plus tolerating the refused write; a deterministic regression test fails on the old code and passes on the new. The race predates M18 and is rare (it failed once in many runs), so it is **not proof that the race can no longer occur** in other ways, only that this path is closed.

## Exact limitations of the model-free build

* A word CMUdict lacks **stops generation**; poetic and dialect forms are common in this repertoire (`ev'ry`, `heav'n`, `o'er`, `'neath`, `e'en`, `lov'd`, `mammy`, `alabamy`, `mmm` were the 9 of 33 spot-checked words that are missing). The only remedy today is to **respell the word in the score**; BLT never changes the score. A phonetic override is designed, not built.
* A follower voice that holds one note under several Lead syllables keeps only the first syllable fragment (for example `to` of `together`); if that is not a dictionary word BLT stops and marks it "a syllable of a longer word". Remedy: a lyric of its own for that voice in the score.
* A syllable engine can answer "not enough extension notes" when a word has more vowels than notes; this also stops generation, with the engine's message.
* The default engine does no lookup, so a mis-spelled alias is found only after rendering (as silent notes).
* A voicebank's own pronunciation dictionary is used by the render check but not by the `--lookup-words` helper.
* `onnxruntime.dll` is not shipped; the managed wrapper `Microsoft.ML.OnnxRuntime.dll` (a OpenUtau dependency, no native code behind it) is still in the host folder and is accounted for in the licence audit and the allow-list.
* The Arpasing+/English C+V engines, Vogen, VOICEVOX and the plus dictionary are absent (unchanged since M16/M17). Everything in `docs/KNOWN-LIMITATIONS.md` still applies, in particular: **not verified with an English voicebank, nor on a clean machine, nor with users**; the Qt GC workaround is test-only and the cause is unexplained.

**Is more user-facing functionality essential before release?** My assessment, which a person should confirm: **no feature is essential**; the release candidate does what it claims and refuses where it cannot. Two things are strongly advisable but not blocking: (a) the **phonetic override** (the next milestone), because respelling changes the written score and barbershop repertoire is full of such words; (b) a listening verdict from the person-run English test, without which "intelligible English singing" stays unverified. The message at a blocked word already tells the singer how to respell.

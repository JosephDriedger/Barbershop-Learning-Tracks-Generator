# Native (compiled) dependencies in the package

Packet for a qualified, independent reviewer (gate item `native-dependencies-review`). Written in M17. It lists every kind of compiled code in BLT's package, who made it, under which licence, what BLT
ships to satisfy that licence, and what is still open. The file-by-file mapping (456 files, each to a component of `packaging/components.json`, with SHA-256 and size) is generated by every package build into
`inventory.json` (`research-output/release/artifacts/inventory.json`; part of the review kit); the build **fails** if a file belongs to no component. The licence and notice texts are in the package's `NOTICES.txt` and `licenses\`.

## 2. What changed in M17

* **The g2p model and `onnxruntime.dll`**: the second is shipped only to run the first, and the first has no documented training data or licence ([../g2p-model-provenance.md](../g2p-model-provenance.md)). A build without the model
  ships neither; `packaging/verify_host_inventory.py` enforces the pair.
* **Nothing can come back by accident**: `compliance/host-inventory.json` allow-lists every embedded resource and phonemizer of the host, `packaging/verify_absent_data.py` searches every file for removed data, and
  `packaging/inventory.py` refuses a file with no component. All three run in the package build.

## 3. Questions for the reviewer

1. Are the licence conclusions in §1 right, in particular: PLATINUM (no licence text in the files), the GCC Runtime Library Exception for the statically linked libgfortran, the UTF.Unknown tri-licence, and onnxruntime's third-party list?
2. For the dependencies BLT did not re-derive (NumPy's wheel inventory, onnxruntime's notices, the .NET runtime pack), is relying on the vendor's published notices enough?
3. Is it acceptable to ship worldline.dll as a BLT build of OpenUtau's sources (MIT) with the statically linked libraries listed above, given the notices shipped?
4. Is requiring the Visual C++ runtime of the user (instead of shipping it) compliant with Microsoft's terms as BLT uses them? (BLT concluded yes; it is asking because a mistake here would sit in every install.)
5. Anything in the file-level inventory that you would want to see re-examined?
